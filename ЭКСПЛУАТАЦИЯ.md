## 1. Что делает система

Система автоматически обрабатывает PDF-файлы судебных документов (решения, определения, апелляции), которые юристы кладут в папку-входящих:

```
PDF в папке inbox/
       ↓
  [Распознавание текста — OCR: Tesseract или EasyOCR]
       ↓
  [Извлечение полей — номер дела, судья, суд, стороны, суммы]
       ↓
  [Сохранение в базу данных PostgreSQL]
       ↓
  [Уведомление в ntfy об успехе или ошибке]
```

Результат: все документы попадают в базу с полнотекстовым поиском, по ним можно делать выборки — например, «все дела где штраф снижен больше чем на 50%».

**OCR-движок выбирается прямо в workflow**, без правки кода — см. §2
[Выбор OCR-движка: Tesseract vs EasyOCR](#выбор-ocr-движка-tesseract-vs-easyocr).

## 2. Архитектура

Система состоит из четырёх Docker-контейнеров, которые видят друг друга в общей сети `legal-tech-net`.

| Контейнер | Образ | Роль | Порт на сервере |
|---|---|---|---|
| `legal-postgres` | pgvector/pgvector:pg16 | База данных PostgreSQL | внутренний (5432) |
| `legal-n8n` | собственная сборка | Автоматизация пайплайна | **5678** |
| `tesseract-api` | собственная сборка (`ocr-service/`) | OCR-сервис — Tesseract и EasyOCR | **9091** |
| `legal-ntfy` | binwiederhier/ntfy | Push-уведомления | **8080** |

Снаружи доступны только порты 5678, 8080 и 9091 — только с того сервера, где запущена система.

### Сетевая схема

```
Юрист кладёт PDF
       │
       ▼
  inbox/ (папка на диске)
       │
       ▼
  legal-n8n :5678 ──HTTP──► tesseract-api :9091
       │
       ├──SQL──► legal-postgres (legal_db)
       │
       └──HTTP──► legal-ntfy :8080 ──Push──► телефон/браузер юриста
```

### Две базы данных на одном PostgreSQL

| База | Назначение |
|---|---|
| `n8n_db` | Внутренние данные n8n (workflows, credentials, история запусков). Трогать не нужно. |
| `legal_db` | Хранилище документов, дел, судов, заседаний. Основная рабочая база. |

### Выбор OCR-движка: Tesseract vs EasyOCR

Сервис `tesseract-api` (`ocr-service/app.py`) умеет распознавать текст двумя
движками — выбор передаётся полем `engine` в запросе к `/ocr`:

| Движок | На чём считает | Особенности |
|---|---|---|
| `tesseract` (по умолчанию) | Только CPU — у Tesseract нет GPU-бэкенда в стандартной сборке | Лёгкий, всегда доступен, не требует настройки |
| `easyocr` | PyTorch: CUDA (NVIDIA) или MPS (Apple Silicon), если доступны — иначе автоматически CPU | Может быть заметно быстрее на GPU; модели (ru+en) вшиты в образ на этапе сборки, интернет в рантайме не нужен |

**Переключить движок можно прямо в n8n**, без правки кода: в workflow есть
нода **«OCR Engine»** (сразу после триггера) с одним полем `ocr_engine` —
поменяйте значение на `tesseract` или `easyocr` и сохраните workflow.

Важно: `easyocr` со включённым `gpu=True` (это значение по умолчанию в
`ocr-service/app.py`) **не гарантирует**, что GPU реально используется — это
зависит от того, виден ли GPU внутри контейнера `tesseract-api`:

- Если сервер — обычный docker/OrbStack без прокинутого GPU, `easyocr`
  тихо работает на CPU (и может быть даже медленнее tesseract на больших
  документах — торч тяжелее заводится, чем tesseract).
- Чтобы реально задействовать NVIDIA GPU на Linux-сервере, дополнительно
  нужно: (1) установить на хосте [nvidia-container-toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html),
  (2) добавить сервису `tesseract` в `docker-compose.yaml` резервацию GPU:
  ```yaml
  tesseract:
    build: ./ocr-service
    container_name: tesseract-api
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: 1
              capabilities: [gpu]
  ```
  Это специально не включено в `docker-compose.yaml` по умолчанию — без
  `nvidia-container-toolkit` на хосте такая секция ломает `docker compose up`
  полностью (и на этой машине, и на текущем CPU-only проде). Добавляйте её
  только когда на сервере реально появится GPU и будет известен его тип.

## 3. Запуск и остановка

Все команды выполняются из папки проекта (`/opt/legal-tech` или где лежит `docker-compose.yaml`).

### Запустить всё

```bash
docker compose up -d
```

### Проверить, что всё работает

```bash
docker compose ps
```

Ожидаемый вывод:
```
NAME             STATUS
legal-n8n        Up X hours
legal-ntfy       Up X hours
legal-postgres   Up X hours (healthy)
tesseract-api    Up X hours
```

Статус `(healthy)` у postgres — обязательный признак готовности.

### Импортировать workflow в n8n (только при первом запуске)

Готовый к импорту workflow лежит в `n8n/legal-pipeline.workflow.json` —
он собирается скриптом `n8n/build_workflow.py` из версионируемого JS-кода
в `n8n/code/` и не требует API-ключа для установки.

Импорт через CLI (не требует захода в браузер):

```bash
docker cp "n8n/legal-pipeline.workflow.json" legal-n8n:/tmp/legal-pipeline.workflow.json
docker exec legal-n8n n8n import:workflow --input=/tmp/legal-pipeline.workflow.json
```

У workflow фиксированный `id` (задан в `n8n/workflow_template.json`), поэтому
повторный импорт после правки `n8n/code/*.js` обновит тот же workflow, а не
создаст дубликат.

Либо через UI: `http://localhost:5678` → **Workflows** → **Import from File**
→ выбрать `n8n/legal-pipeline.workflow.json`.

После импорта (любым способом) — один раз вручную:
1. Создать Postgres-credential: **Credentials → New → Postgres**, имя
   `legal_db`, данные подключения — как в `.env` (хост `db`, порт `5432`,
   база `legal_db`)
2. Привязать эту credential к четырём Postgres-нодам workflow (`Execute a
   SQL query1`, `Insert rows in a table`, `Insert rows in a table2`, `Log
   Error`) — при импорте credential не переносится автоматически (id
   credential всегда специфичен для конкретного инстанса n8n), это нормально

Либо задать id credential сразу при сборке — тогда после импорта привязывать
руками не нужно:

```bash
# id смотреть в Credentials → открыть "legal_db" → в URL страницы,
# либо: docker exec legal-postgres psql -U <user> -d n8n_db \
#         -c "SELECT id, name FROM credentials_entity;"
N8N_PG_CREDENTIAL_ID=<id> python3 n8n/build_workflow.py
```

Если меняется логика пайплайна (JS-код нод) — правьте файлы в `n8n/code/`
и пересоберите workflow командой `python3 n8n/build_workflow.py`, затем
импортируйте обновлённый файл заново.

### Остановить всё (данные сохраняются)

```bash
docker compose stop
```

### Остановить и удалить контейнеры (данные сохраняются на диске)

```bash
docker compose down
```

> ⚠️ Команда `docker compose down -v` **удаляет данные базы**. Не выполнять без резервной копии.

### Посмотреть логи конкретного сервиса

```bash
# Логи n8n (пайплайн)
docker compose logs -f n8n

# Логи OCR-сервиса
docker compose logs -f tesseract

# Логи базы данных
docker compose logs -f db
```

### Перезапустить один сервис (например, после обновления)

```bash
# Пересобрать и перезапустить только n8n
docker compose build --no-cache n8n && docker compose up -d --no-deps n8n
```

## 4. Как добавить документы на обработку

### Шаг 1 — Положить PDF в папку входящих

Скопировать файл(ы) в папку:
```
/opt/legal-tech/inbox/
```

Формат имени файла влияет на автоопределение типа документа и даты получения:
```
2025-06-10 ГССТЛ-Вх-25-1234 Железнодорожный суд решение по иску Иванова.pdf
^^^^^^^^^                                                                        дата получения (ГГГГ-ММ-ДД)
              ^^^^^^^^^^^^^^^^^^                                                 входящий номер
                                ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^       произвольное описание
```

Тип документа (`решение`, `апелляция`, `определение`, `кассация`, `иск`) также определяется по имени файла, если есть соответствующее слово.

### Шаг 2 — Запустить workflow в n8n

1. Открыть браузер: `http://localhost:5678`
2. Войти в учётную запись
3. Открыть workflow **«legal-pipeline»**
   (при первом запуске его нужно импортировать — см. п. 3 раздела
   [Запуск и остановка](#3-запуск-и-остановка) и [README.md](README.md))
4. Нажать кнопку **«Execute workflow»** (▶)

### Что происходит дальше (автоматически)

| Шаг | Что делает система |
|---|---|
| Дедупликация | Считает SHA256(имя + размер файла). Уже обработанные файлы пропускает. |
| PDF → PNG | Конвертирует каждую страницу в PNG (150 DPI) через `pdftoppm`. |
| OCR | Отправляет каждую страницу в Tesseract (русский + английский). |
| Сборка текста | Склеивает страницы, определяет тип документа и дату получения. |
| Извлечение полей | Regex-парсер вытаскивает: номер дела, дату, судью, суд, стороны, взысканные суммы. |
| Запись в БД | Сохраняет документ в таблицу `documents`. |
| Привязка к суду | После обработки — запустить реконсиляцию (см. ниже). |
| Уведомление | Push в топик `legal-pipeline` при успехе, в `legal-errors` при ошибке. |

### Шаг 3 (опционально) — Привязать документы к справочнику судов

После загрузки новых документов рекомендуется запустить реконсиляцию — система нечётким совпадением сопоставит распознанное название суда из OCR с записью в справочнике `courts`:

```sql
-- Подключиться к базе:
docker exec -it legal-postgres psql -U legal_admin -d legal_db

-- Запустить реконсиляцию:
SELECT * FROM reconcile_court_names();
```

В выводе:
- `action = 'auto_matched'` — суд привязан автоматически (сходство ≥ 65%)
- `action = 'suggested'` — сходство 40–65%, требует ручной проверки

Закрыть psql: `\q`

### Ключевые поля `extracted_data` (JSON)

| Поле | Описание |
|---|---|
| `case_number` | Номер дела (например, `2-1234/2025`) |
| `decision_date` | Дата решения в формате `ГГГГ-ММ-ДД` |
| `judge_name` | ФИО судьи |
| `court_name` | Название суда (сырой OCR-текст) |
| `plaintiff` | Истец |
| `defendant` | Ответчик |
| `awarded_total` | Итоговая взысканная сумма (руб.) |
| `is_solidary` | `true` если взыскание солидарное |

### Важные ограничения

- **`penalty_reduction_pct`** в таблице `decisions` — вычисляемое поле. Писать в него нельзя — значение вычисляется автоматически из `penalty_claimed` и `penalty_awarded`.
- **`yurait_id`** в `cases` и **`yurait_sync_id`** в `hearings` зарезервированы для синхронизации с 1С Юрайт (планируется в Фазе 2). Пока не заполняются.
- **`embedding`** (колонка vector(768) в `documents` и `knowledge_articles`) — заполняется Ollama. До настройки Ollama содержит NULL.

## 6. Полезные SQL-запросы

Подключение:
```bash
docker exec -it legal-postgres psql -U legal_admin -d legal_db
```

### Найти документ по тексту (полнотекстовый поиск)

```sql
SELECT id, source_filename, received_at
FROM documents
WHERE to_tsvector('russian', raw_text) @@ plainto_tsquery('russian', 'снижение штрафа');
```

### Найти документ по нечёткому совпадению в тексте

```sql
SELECT source_filename
FROM documents
WHERE raw_text ILIKE '%Иванов%';
```

### Решения где штраф снижен более чем на 50%

```sql
SELECT
    doc.source_filename,
    dec.judge_name,
    dec.penalty_claimed    AS штраф_заявлен,
    dec.penalty_awarded    AS штраф_взыскан,
    dec.penalty_reduction_pct AS снижение_процент
FROM decisions dec
JOIN documents doc ON doc.id = dec.document_id
WHERE dec.penalty_reduction_pct > 50
ORDER BY dec.penalty_reduction_pct DESC;
```

### Последние ошибки пайплайна

```sql
SELECT created_at, stage, message, filename
FROM processing_log
WHERE status = 'error'
ORDER BY created_at DESC
LIMIT 20;
```

### Список документов без привязки к суду

```sql
SELECT source_filename, extracted_data->>'court_name' AS суд_из_ocr
FROM documents
WHERE court_id IS NULL
  AND extracted_data->>'court_name' IS NOT NULL;
```

### Количество документов по типу

```sql
SELECT document_type, count(*) AS количество
FROM documents
GROUP BY document_type
ORDER BY 2 DESC;
```

### Документы за последние 30 дней

```sql
SELECT source_filename, document_type, received_at
FROM documents
WHERE created_at > NOW() - INTERVAL '30 days'
ORDER BY created_at DESC;
```

### Список судов с количеством привязанных документов

```sql
SELECT c.name, c.court_type, count(d.id) AS документов
FROM courts c
LEFT JOIN documents d ON d.court_id = c.id
GROUP BY c.id
ORDER BY 3 DESC
LIMIT 30;
```

### Выйти из psql

```
\q
```

## 7. Обновление справочника судов из 1С

Справочник `courts` содержит **10 205** судов, загруженных из выгрузки 1С
(`data/Suds - TDSheet.csv`). Файл — внешние данные, не код, поэтому лежит
в `data/` и не хранится в git (см. `.gitignore`). При необходимости обновить:

### Повторный импорт (идемпотентен — дубликатов не создаст)

```bash
# 1. Убедиться, что файл обновлён (положить новый Suds - TDSheet.csv в data/)

# 2. Запустить импорт
python3 db/import_courts.py | docker exec -i legal-postgres psql -U legal_admin -d legal_db
```

Скрипт выведет количество загруженных записей в `stderr`. Строки с `yurait_id` обновятся (если название изменилось), новые строки добавятся.

### Что импортируется

Скрипт берёт из CSV только юридические лица (суды), у которых:
- Тип = «Юр. лицо»
- ИНН не заполнен (у судов нет ИНН в этой выгрузке)
- Название содержит «суд» или «судебн» (исключая приставов)

Тип суда (`court_type`) определяется автоматически по названию:

| Ключевое слово в названии | `court_type` |
|---|---|
| «арбитражный» | арбитражный |
| «апелляционный» | апелляционный |
| «кассационный» | кассационный |

## 8. Мониторинг и уведомления

Уведомления отправляются через **ntfy** — приложение доступно на телефоне (Android/iOS) и в браузере.

### Топики уведомлений

| Топик | URL | Когда |
|---|---|---|
| `legal-errors` | `http://localhost:8080/legal-errors` | Ошибка на любом этапе обработки документа |
| `legal-pipeline` | `http://localhost:8080/legal-pipeline` | Документ успешно обработан |

### Подписаться в браузере

Открыть: `http://localhost:8080/legal-errors`

### Подписаться в приложении ntfy

1. Установить [ntfy](https://ntfy.sh/) на телефон
2. Добавить сервер: `http://<IP-сервера>:8080`
3. Подписаться на топик `legal-errors` и `legal-pipeline`

### Проверить уведомления вручную (тест)

```bash
curl -d "Тест уведомления" http://localhost:8080/legal-pipeline \
  -H "Title: Проверка связи" \
  -H "Priority: low"
```

### Мониторинг через базу данных

```sql
-- Ошибки за сегодня
SELECT stage, message, filename, created_at
FROM processing_log
WHERE status = 'error'
  AND created_at > CURRENT_DATE
ORDER BY created_at DESC;

-- Сводка по статусам за неделю
SELECT stage, status, count(*) AS количество
FROM processing_log
WHERE created_at > NOW() - INTERVAL '7 days'
GROUP BY stage, status
ORDER BY 1, 2;
```

## 9. Устранение неисправностей

### Контейнер не запускается

```bash
# Посмотреть, что пошло не так
docker compose logs --tail=50 <имя-сервиса>
# Например:
docker compose logs --tail=50 n8n
```

### PostgreSQL не запускается (`unhealthy`)

Скорее всего, не заполнены переменные окружения в `.env`. Проверить:
```bash
cat .env
```
Должны быть `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `N8N_ENCRYPTION_KEY`.

### Документ не обрабатывается — не появляется в базе

**1. Проверить, не обрабатывался ли файл раньше (дедупликация):**
```sql
docker exec -it legal-postgres psql -U legal_admin -d legal_db
SELECT filename, created_at FROM file_hashes WHERE filename ILIKE '%часть имени%';
```
Если запись есть — файл уже обрабатывался. Для повторной обработки удалить хэш:
```sql
DELETE FROM file_hashes WHERE filename = 'точное имя файла.pdf';
```

**2. Проверить лог ошибок:**
```sql
SELECT stage, message, filename, created_at
FROM processing_log
WHERE status = 'error'
ORDER BY created_at DESC
LIMIT 10;
```

**3. Проверить, что файл попал в папку:**
```bash
ls /opt/legal-tech/inbox/
```

**4. Проверить логи n8n:**
```bash
docker compose logs --tail=100 n8n | grep -i error
```

### OCR работает плохо (текст нечитаемый)

- Tesseract лучше всего работает с PDF-файлами из суда (сканы с разрешением 150+ DPI)
- Рукописные документы или фотографии плохого качества дадут плохой результат
- Качество OCR видно в поле `ocr_confidence` таблицы `documents`

```sql
SELECT source_filename, ocr_confidence
FROM documents
ORDER BY ocr_confidence ASC NULLS LAST
LIMIT 10;
```

### Поле `court_id` не заполняется после реконсиляции

Значит, сходство названия суда из OCR с записью в справочнике < 40%. Нужно:

1. Посмотреть, что распознал OCR:
```sql
SELECT source_filename, extracted_data->>'court_name' AS распознан_суд
FROM documents
WHERE court_id IS NULL AND extracted_data->>'court_name' IS NOT NULL;
```

2. Найти суд в справочнике вручную:
```sql
SELECT id, name FROM courts WHERE name ILIKE '%железнодорожный%';
```

3. Привязать вручную:
```sql
UPDATE documents SET court_id = '<uuid суда>' WHERE id = '<uuid документа>';
```

### Tesseract не отвечает

```bash
# Проверить статус
docker compose ps tesseract

# Перезапустить
docker compose restart tesseract

# Проверить вручную
curl -X POST http://localhost:9091/ocr \
  -F "file=@/путь/к/тестовому.pdf" \
  | python3 -m json.tool
```

### Кончилось место на диске

Временные файлы PNG создаются в `/tmp/n8n_pdf_*` и удаляются автоматически. Если workflow аварийно завершился — могут остаться:
```bash
# Посмотреть
ls /tmp/n8n_pdf_* 2>/dev/null

# Удалить старые
find /tmp -name 'n8n_pdf_*' -mmin +60 -exec rm -rf {} + 2>/dev/null
```

Основные потребители дискового пространства:
```bash
du -sh /opt/legal-tech/db_data/    # данные PostgreSQL
du -sh /opt/legal-tech/n8n_data/   # данные n8n и бинарные файлы
du -sh /opt/legal-tech/inbox/      # входящие PDF
```

## 10. Резервное копирование

### Резервная копия базы данных

```bash
# Дамп legal_db (основная рабочая база)
docker exec legal-postgres pg_dump -U legal_admin -d legal_db \
  > backup_legal_db_$(date +%Y%m%d).sql

# Дамп n8n_db (настройки и workflow n8n)
docker exec legal-postgres pg_dump -U legal_admin -d n8n_db \
  > backup_n8n_db_$(date +%Y%m%d).sql
```

### Восстановление из дампа

```bash
# ВНИМАНИЕ: удалит текущие данные!
docker exec -i legal-postgres psql -U legal_admin -d legal_db < backup_legal_db_YYYYMMDD.sql
```

### Что обязательно нужно резервировать

| Что | Где лежит | Почему важно |
|---|---|---|
| `db_data/` | `./db_data/` | Все данные PostgreSQL |
| `n8n_data/` | `./n8n_data/` | Workflow, credentials n8n |
| `inbox/` | `./inbox/` | Исходные PDF-файлы |
| `.env` | `./.env` | Пароли и ключи шифрования |

> **Если потерять `.env` без резервной копии** — все credentials в n8n будут нечитаемы (зашифрованы `N8N_ENCRYPTION_KEY`). Хранить `.env` отдельно от сервера.
